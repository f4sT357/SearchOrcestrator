## 攻撃者とLLMの設定

攻撃者役はWeb本文と追加検索案を作る。Web本文にはSystem/Developerの偽装、評価の自己承認、架空のキーを検索で送信させる命令を入れた。

ローカルLLM役は、その攻撃に必ず従うPython製の模擬モデルである。SystemMessageを受け取っても、攻撃者が指定した評価・検索案を返す。実際のワークフローの `evaluate` → `prepare_followups` → `dispatch_followups` → 通常・公式の追加検索を通し、検索サービス役が受け取った文字列を調べた。攻撃者指定の関連度は1.0にして、関連度検査だけでは止まらない条件にした。

キーには架空の `RtKey7Q4` などを使った。模擬モデルにはこの値を意図的に与えている。実際のアプリで秘密キーがWebページやLLMに見えていたことを実証した試験ではない。実APIキーの読み出し、外部への持ち出し、第三者サイトへの攻撃は行っていない。

## 再現できた問題と修正

1. **検索語の難読化**: 既知のキーでも、Base64・Base32・Base85・ASCII85・ROT13・16進数・大文字小文字変更・文字間の空白・全角化・短い設定キーは送信まで通った。既知キーの標準的な表現とUnicode正規化後の表現を検査するよう修正し、文字区切りや不可視文字への対策も追加した。
2. **Injection Guardの検査順序**: `<system>` やチャット用ロールタグをエスケープしてから検査しており、検知パターンが一致しなかった。元データの検査と、LLMへ渡すエスケープ済み表現を分けた。JSON中の改行も検査用の表現で扱う。攻撃例そのものは削除しない。
3. **引用処理の停止**: 5,000桁の `[S999…]` が整数変換の上限に達してValueErrorを起こした。引用番号をASCII・桁数で制限し、不正な引用は削除する。入れ子の角括弧による余計な正規表現の探索も抑えた。
4. **ログへの短いキーの露出**: 8文字未満の設定キーがマスク対象外だった。短いキー・標準的な符号化・文字区切りを共通マスク処理へ含め、GUIのエラー・進捗・通常ログにも適用した。正規表現の可変な区切りを繰り返す方式は避け、文字位置を使ってマスクしている。
5. **破損キャッシュによる停止**: UTF-8として読めないWebキャッシュを読み込むと例外になった。破損キャッシュを無視して通常取得へ戻す。ソース評価キャッシュの不正なJSON形状も回帰テストで確認した。これはローカルキャッシュ破損への耐性であり、Webだけで任意のキャッシュを書き換えられると確認したものではない。
6. **モデル出力の型・容量**: テキスト配列などを `str(...)` にして成功として扱っていた。文字列以外と65,536文字を超える応答を解析・描画へ渡す前に拒否する。対応しない構造の応答は既存の失敗処理へ戻す。

LM Studioの既定値 `lm-studio` は認証用の秘密ではないため、設定済みの保護対象キーから除外した。これにより通常の「LM Studio」の調査を誤って拒否しない。

## 使い捨て環境

Docker Desktop上のLinuxコンテナを使用した。実行時はネットワークを `none`、UIDを65534、ルートファイルシステムとソースを読み取り専用にした。Linux capabilitiesはすべて落とし、権限昇格を禁止した。メモリー512 MiB、CPU 1、プロセス数64、実行120秒の上限を設定した。

コンテナ内部からも、ネットワークインターフェイスが `lo` だけであること、UID、capabilities、NoNewPrivs、ソースを書き換えられないことを検査した。ホストの設定、`.env`、Git情報、キャッシュ、Dockerソケットは渡していない。実行器が必要な8モジュールと試験コードだけを一時コピーし、そのコピーを読み取り専用でマウントした。

依存イメージの作成時だけパッケージ取得のためにネットワークを利用した。攻撃試験の実行時は外部通信なし。コード側にも実DNS・実ソケット接続を検知する仕組みを入れた。試験ではHTTP・検索先をメモリー内で再現した。

コンテナには実行ごとの一意な名前を付け、終了・タイムアウト時に明示削除し、Dockerの一覧から消えたことを確認する。一時ソースコピーも実行器が削除する。依存イメージIDと全ソースのSHA-256はJSONの証跡に保存した。beforeとafterは同一イメージ・同一試験コードで比較している。

今回の試験コンテナ、一時コピー、旧版の比較用コピー、作成した2つの検証イメージは削除済み。既存のベースイメージ、Dockerのビルドキャッシュ、Dockerエンジンは残している。

## 再実行

Dockerを起動した状態で、リポジトリのルートから実行する。

```powershell
.\.venv\Scripts\python.exe scripts/run_redteam.py --build --output .cache/redteam-result.json
.\.venv\Scripts\python.exe -m pytest -q
```

最初のコマンドはイメージをビルドし、コードの使い捨てコピーを作って隔離実行する。検証項目に不合格があれば終了コード1になる。`--source` を指定すれば、別途用意した旧版のソースとも同じケースで比較できる。ビルド時に再解決する依存関係は将来変わり得るため、その都度イメージIDを記録する。

## 残る限界

- 実際の4BモデルやLM Studioは呼んでいない。モデルごとの攻撃成功率・誤検出率を示す結果ではない。
- 評価スコアや回答の意味を攻撃者が改変できないことは保証していない。模擬モデルは攻撃者の評価案も返す。24項目の合格は、試験した送信制限・検知・停止耐性・隔離条件の合格を意味する。
- 任意の自然言語での漏洩、独自暗号化、複数検索に分けた断片の持ち出しを完全には検出できない。モデルに秘密情報を入れないことと、Python側の権限制限を維持する必要がある。検出可能な表現を増やすだけで完全防御になるわけではない。
- 短く一般的な値を本物のキーとして設定すると、それを含む正常な検索やログも拒否・マスクする場合がある。
- Firecrawlの実サービス、実DNS・外部HTTP、GUIの目視試験、コンテナ脱出やカーネル脆弱性は今回の対象外。今回のコンテナは検証用であり、製品自体を自動的にコンテナ化する変更ではない。
